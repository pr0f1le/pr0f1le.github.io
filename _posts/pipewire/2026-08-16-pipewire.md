最近想制作一个简单的音乐制作软件，还要实时显示出各个频率的强度，显示音乐播放进度等等。

拆分这个小项目，我打算先从播放音频开始，于是学习一下pipewire。

## 第一个 pipewire 客户端

```c
#include <pipewire/pipewire.h>
#include <stdio.h>

int main(int argc, char *argv[]) {

    // use pw_init before use pipewire functions
    pw_init(&argc, &argv);

    fprintf(stdout,
            "libpipewire header version %s\n"
            "libpipewire lib version %s\n",
            pw_get_headers_version(), pw_get_library_version());

    return 0;
}
```

这份代码来自 [Pipewire Tutorial](https://docs.pipewire.org/page_tutorial1.html)

编译：

```bash
cc -Wall main.c -o main $(pkg-config --cflags --libs libpipewire-0.3)
```

这个程序只是链接了 `libpipewire-0.3.so.0`{:.filepath} 并且显示了 pipewire 库的版本，并没有
真正使用 pipewire 的功能。

根据 pipewire 的文档，使用 pipewire 的函数之前需要调用 `pw_init()` ，它会初始化 pipewire 系统
并设置一些调试信息。

## pipewire 事件

pipewire 通过事件和回调实现任务的处理。而要实现事件和回调模型一般就会实现一个事件循环。

pipewire 提供了两个事件循环抽象，`struct pw_main_loop` 和 `struct pw_thread_loop`。一般使用 `pw_main_loop` 就行。

在 pipewire 中，为了管理事件循环中的资源，需要获取事件循环的上下文 `struct pw_context`

```c
struct pw_main_loop *loop;
struct pw_context *context;
loop = pw_main_loop_new(NULL /*props*/);
context = pw_context_new(pw_main_loop_get_loop(loop),
                         NULL /*props*/,
                         0 /*user_data_size*/);
```

有了上下文就可以链接到 pipewire 守护进程了

```c
struct pw_core *core;
core = pw_context_connect(context,
                          NULL /*properties*/, 
                          0 /*user_data_size*/);
```

这里会在客户端和守护进程之间创建一个套接字，并创建一个用于核心的代理对象。

这里提到了 `代理 proxy` 和 `对象 object` 的概念，稍后进行讲解。

有了连接之后就可以向服务器发送消息，并接收各种事件了。

## 接收并处理事件

核心对象有 `struct pw_core_events` 事件，其中包含 `info`，`done`，`ping` 等等事件回调函数，由用户自己设置

[Pipewire Tutorial2](https://docs.pipewire.org/page_tutorial2.html) 和 [Pipewire Tutorial3](https://docs.pipewire.org/page_tutorial3.html) 
使用 registry 对象和事件列出所有 objects，[Pipewire Tutorial4](https://docs.pipewire.org/page_tutorial4.html) 使用 stream 对象和事件播放了
特定频率的声音。

在 pipewire 中有很多这样的对象和相关事件

以 Tutorial3 为例，列出所有对象

在经过前面的步骤连接到 pipewire 服务器后，获取一个注册表对象

```c
struct pw_registry *registry;
registry = pw_core_get_registry(core,
                                PW_VERSION_REGISTRY,
                                0 /*user_data_size*/);
```

然后使用一个监听器监听相关对象

```c
struct spa_hook registry_listener;
spa_zero(registry_listener);
pw_registry_add_listener(registry,
                         &registry_listener,
                         &registry_events,
                         NULL);
```

其中注册表事件绑定回调函数

```c
static void registry_event_global(void *data, uint32_t id, uint32_t permissions,
                                  const char *type, uint32_t version,
                                  const struct spa_dict *props) {
    printf("object: id:%u, type:%s/%d\n", id, type, version);
}

static const struct pw_registry_events registry_events = {
    PW_VERSION_REGISTRY_EVENTS,
    .global = registry_event_global,
};
```

为了确保所有任务已经完成，我们需要监听 core 的完成事件，然后使用 `pw_main_loop_quit()` 退出事件循环

```c
struct data {
    int pending;
    struct pw_main_loop *loop;
};

static void on_core_done(void *data, uint32_t id, int seq) {
    struct data *d = data;

    if (id == PW_ID_CORE && seq == d->pending) {
        pw_main_loop_quit(d->loop);
        puts("Everything done !");
    }
}

static void core_work(struct pw_core *core, struct pw_main_loop *loop) {
    static const struct pw_core_events core_events = {
        PW_VERSION_CORE_EVENTS,
        .done = on_core_done,
    };

    struct data d = {.loop = loop};
    struct spa_hook core_listener;
    int err;

    pw_core_add_listener(core, &core_listener, &core_events, &d);

    d.pending = pw_core_sync(core, PW_ID_CORE, 0 /*seq*/);

    if ((err = pw_main_loop_run(loop)) < 0)
        printf("main_loop_run error:%d!\n", err);

    spa_hook_remove(&core_listener);
}
```

在 `core_work()` 中添加了 core 监听器，并将 `done` 事件绑定到 `on_core_done()` 上，同时传入 `data` ，这样在
事件处理内部就可以控制退出 `main_loop` 。

`pw_core_sync()` 会向 core 发送消息，表示希望在该客户端中 `pw_core_sync()` 之前的所有方法以及由此产生的事件处理完
后发送 done 消息给客户端。这个函数返回一个 seq number，而这个 seq number 也是 core 发送给客户端的 done 事件的 seq number，
回调函数可以以此判断是哪个 done 事件。

然后客户端会收到 core 的 done 事件，调用 `on_core_done()` ，在这个例子中，这个 done 事件收到后，客户端主动关闭事件循环并退出。

`pw_core_get_registry()` 被调用后，服务器会立刻向客户端发送当前所有全局对象的列表，但事件循环还没有开启，数据还没有被消费，客户端
还没有知觉，然后 `pw_core_sync()` 请求了一个 done 事件，此时列表里先是一些 global 事件，然后是一个 done 事件。
main_loop 启动后，global 事件立即被消费，直到 global 事件消费完后，done 事件被消费，调用 `on_core_done()` 。

这就是这个枚举所有全局对象的程序的执行流程。

## 播放声音

播放声音需要 stream 对象处理 process 事件，也就是说我们需要创建 stream 对象 并设置 process 的回调

幸运的是，pipewire 提供了更简单的管理 stream 的方式，不必像 registry 一样需要得到 core 对象和 listener，而是自动管理它们

```c
struct pw_stream *stream = pw_stream_new_simple(
        pw_main_loop_get_loop(data.loop), "music-src" /* name */,
        pw_properties_new(PW_KEY_MEDIA_TYPE, "Audio",
                          PW_KEY_MEDIA_CATEGORY, "Playback",
                          PW_KEY_MEDIA_ROLE, "Music",
                          NULL),
        &stream_events, &data);
```

这里 `stream_events` 是 stream 事件，`data` 是自定义数据，就如之前提到的一样

`stream_events` 管理 process 事件也如之前一样

```c
static void on_process(void *userdata) {
    struct data *data = userdata;

    struct pw_buffer *b;
    /* some music porcedure ... */
    pw_stream_queue_buffer(data->stream, b);
}

static const struct pw_stream_events stream_events = {
    PW_VERSION_STREAM_EVENTS,
    .process = on_process,
};
```

有点不一样的是，stream 对象一定要设置 properties ，用于确定 stream 的类型和工作方式

```c
...
        pw_properties_new(PW_KEY_MEDIA_TYPE, "Audio",
                          PW_KEY_MEDIA_CATEGORY, "Playback",
                          PW_KEY_MEDIA_ROLE, "Music",
                          NULL),
...
```

`Audio` 表示媒体类型为音频，只涉及音频数据，其他选项有 `Video`，`Midi`
`Playback` 表示回放或播放，其他选项有 `Capture`，`Monitor` 等
`Music` 表示这是一个音乐播放器客户端，pipewire 内部会有相应的优化，其他选项有 `Movie`，`Game` 等，对应优化可能为优化音画同步，降低声音延迟等

这里的三个 kv 对表示当前这个客户端是一个音乐播放器。

但在播放音频之前，我们需要知道音频的一些参数，例如声道数，采样率，位深度等，同样的，pipewire 也需要知道，这样才能正确解析原始音频数据

在 pipewire 中，这需要使用一个结构体来设置

```c
#define DEFAULT_CHANNELS 2
#define DEFAULT_RATE 44100

const struct spa_pod *params[1];
struct spa_pod_builder b = SPA_POD_BUILDER_INIT(buffer, sizeof(buffer));
params[0] = spa_format_audio_raw_build(
                &b, SPA_PARAM_EnumFormat,
                &SPA_AUDIO_INFO_RAW_INIT(
                    .format = SPA_AUDIO_FORMAT_S16,
                    .channels = DEFAULT_CHANNELS,
                    .rate = DEFAULT_RATE ));
```

这里的 pod 是 pipewire 的二进制序列化数据结构，需要使用 `struct spa_pod_builder` 进行构建，主要是二进制数据需要 buffer 来存储

这里可以看到传入的参数有
- 位深度 `.format` ，值为 `_S16` ，表示用 16 位带符号整数对声音信号进行量化/采样，还可以使用 8 位整数，24 位浮点数，32 位浮点数等等格式
- 声道数 `.channels` 为 2,
- 采样率 `.rate` 为 44100.

然后将连接到这个 stream 上

```c
pw_stream_connect(data.stream,
                  PW_DIRECTION_OUTPUT,
                  PW_ID_ANY,
                  PW_STREAM_FLAG_AUTOCONNECT |
                  PW_STREAM_FLAG_MAP_BUFFERS |
                  PW_STREAM_FLAG_RT_PROCESS,
                  params, 1);
```

这里除了设置参数，还设置了 stream 的属性

- `_OUTPUT` 表示这是一个输出声音的客户端
- `_ID_ANY` 表示任意设置 id
- `_FLAG_AUTOCONNECT` 表示自动连接这个 stream
- `_FLAG_MAP_BUFFERS` 表示将 buffer 映射到内存
- `_FLAG_MAP_RT_PROCESS` 表示在实时线程中调用 process 回调，同时回调中必须使用实时安全的函数

`_FLAG_*` 比较多也比较复杂，暂时先用文档中提到的

连接完 stream 终于可以进入 process 回调了，这里就是处理原始音频数据 PCM (Pulse Code Modulation 脉冲编码调制) 的地方

```c
#define NOTE_8(freq)                                                           \
    (struct note) { .freq = (freq), .duration = (DEFAULT_RATE / 8.0f) }
#define NOTE_4(freq)                                                           \
    (struct note) { .freq = (freq), .duration = (DEFAULT_RATE / 4.0f) }
#define NOTE_2(freq)                                                           \
    (struct note) { .freq = (freq), .duration = (DEFAULT_RATE / 2.0f) }
#define NOTE_1(freq)                                                           \
    (struct note) { .freq = (freq), .duration = (DEFAULT_RATE) }

struct note { // 音符
    double freq;        // 频率
    uint32_t duration;  // 持续事件
};

struct data {
    struct pw_main_loop *loop;
    struct pw_stream *stream;

    struct note *notes; // 音符
    size_t n_notes;     // 音符数
    size_t note_count;  // 事件循环内音符计数
    uint32_t current_duration; // 事件循环内音符持续时间

    double acc;         // 累加器，每次事件循环累加 phase

    double period;      // 音符波形周期
    double (*wave_generator)(double phase); // 音符波形
};

double square(double phase) { return phase > 0.5 ? 0 : 1; } // 方波声音

static void on_process(void *userdata) {
    struct data *data = userdata;

    struct pw_buffer *b;

    // 从 stream 中获取 buffer
    if ((b = pw_stream_dequeue_buffer(data->stream)) == NULL) {
        pw_log_warn("out of buffers: %m");
        return;
    }

    struct spa_buffer *buf = b->buffer;

    // 目标音频 memory
    int16_t *dst = buf->datas[0].data;
    if (dst == NULL)
        return;

    // 每帧数据总长度 位深度 x 声道数
    int16_t stride = sizeof(int16_t) * DEFAULT_CHANNELS;

    int n_frames = buf->datas[0].maxsize / stride;

    // pipewire stream 推荐的 n_frames
    if (b->requested) {
        n_frames = SPA_MIN(b->requested, n_frames);
    }

    for (int i = 0; i < n_frames; ++i) {
        // note count
        if (data->current_duration >= data->notes[data->note_count].duration) {
            data->current_duration = 0;
            data->note_count++;
            data->acc = 0;
        }
        if (data->note_count >= data->n_notes) {
            pw_main_loop_quit(data->loop);
        }
        // 计算 phase
        data->acc +=
            data->period * data->notes[data->note_count].freq / DEFAULT_RATE;
        if (data->acc > data->period)
            data->acc -= data->period;
        // fill music data
        for (int c = 0; c < DEFAULT_CHANNELS; ++c) {
            int16_t val =
                data->wave_generator(data->acc) * 32767.0f * DEFAULT_VOLUME; // (int)32767.0f = 0x7fff = 0b111_1111_1111_1111
            *dst++ = val;
        }
        data->current_duration++;
    }

    // 设置数据结构
    buf->datas[0].chunk->offset = 0;               // 数据起点
    buf->datas[0].chunk->stride = stride;          // 每块/帧数据大小
    buf->datas[0].chunk->size = n_frames * stride; // 数据总大小

    // 将 buffer 添加回 stream
    pw_stream_queue_buffer(data->stream, b);
}
```

这里我定义了音符 `struct note` ，包含频率和持续时间，在 `struct data` 中定义了波生成接口和波周期，例如使用方波 `square` 生成声音，周期为 1 ，
在主函数中设置音符列表即可播放声音。
